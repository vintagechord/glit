# 문서 생성 검증

2026-10-25, 실제 고객 자료 없이 합성 음반 2종과 온라인 MV로 19개 DOCX를 생성했다. 기존 documents 스킬의 `render_docx.py`로 전체 PDF/PNG를 렌더링하고 페이지 배치, 긴 가사 연결, 크레딧, 연락처 표, 방송사 표를 확인했다. 원본 HWP의 요청서 병합 구조와 다른 과거 템플릿을 발견해 원본에서 다시 변환했고, 해당 요청서를 다시 렌더링했다.

최종 요청서는 15열 숨은 그리드와 원본 병합을 보존한다. 상단 폼은 첫 페이지에 한 번, 트랙은 그 아래부터 연속한다. 90명 합성 크레딧은 글자 축소나 이름 삭제 없이 2페이지에 이어진다. 반복 트랙 셀의 과도한 1.6배 줄간격만 1.15배로 정리했다. 상단 정보·열·여백·글자 크기는 유지했다.

130줄 합성 전체 가사집은 같은 변환 환경에서 기본 4페이지, 인쇄용 문단 연결 후 2페이지다. 개별 가사와 심의폼·앨범정보는 원래 줄바꿈을 유지한다. 줄바꿈만 정규화한 내용 비교, DOCX ZIP CRC, HTML escaping, 타이틀/Inst 구분, 서류 수와 DOCX 전용 ZIP을 테스트한다.

```sh
node --test tools/onside-desk/tests/documents.test.mjs
node tools/onside-desk/tests/render-fixtures.mjs /tmp/onside-new-document-qa
```

`onside-doc-qa:local`은 이 맥에 준비한 독립 Docker 이미지다. 프로그램은 이 이미지가 실행 가능할 때만 전체 가사집의 실제 페이지 수를 계산한다. 변환은 `--network none`으로 로컬에서 수행한다. Docker가 꺼져 있거나 이미지가 없으면 자료 생성은 계속되며, 원문 줄 구성을 보존하고 페이지 미검증 경고를 남긴다. 재구축이 필요할 때:

```sh
docker build -t onside-doc-qa:local tools/onside-desk/qa
```

별도 workspace dependency loader가 없는 환경이므로 기존 프로젝트의 문서 라이브러리와 격리 컨테이너를 사용했다. 사용자 데스크톱 Office 앱을 자동 조작하지 않았다. 원본 HWP의 전체 텍스트·표는 pyhwp로 추출했으며, Word를 직접 열었다고 주장하지 않는다. 검수 환경에는 원본 바탕/굴림 글꼴이 없어 Noto CJK 등 대체 글꼴이 쓰인다. 실제 Word·한컴의 페이지 수는 달라질 수 있다. 개별 고객 신청은 자동으로 육안 검증 완료 처리하지 않는다.

PBC/TBS의 예시 파일명과 문서 제목이 일반적인 설명과 엇갈려, 최신 프롬프트의 실제 첨부 파일명 우선 규칙을 적용했다. PBC 결과는 「심의 음반 접수 목록」, TBS 결과는 「음원심의신청서」이며 생성 확인사항에 이를 표시한다.
