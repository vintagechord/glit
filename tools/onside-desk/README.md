# 온사이드 심의 데스크

이 맥북에 설치하는 별도 심의 자료 생성·관리 프로그램입니다. 온사이드 신청 데이터를 가져와 이 맥북에 문서와 파일을 보관하고, 심의 결과는 기존 관리자 페이지와 같은 저장 경로로 반영합니다. 문서 보완과 작업 메모는 이 Mac에 보관합니다. **심의 결과 저장**은 관리자·고객 결과 페이지에 즉시 반영하며 이메일을 보내지 않습니다. 이메일은 전체 결과를 확인한 후 별도로 발송합니다.

## 실행

바탕화면의 **온사이드 심의 데스크.app**을 더블 클릭합니다. 실제 프로그램은 `~/Applications/온사이드 심의 데스크.app`에 있습니다. Node 런타임과 필요한 의존성을 앱에 포함해 프로젝트 폴더 없이 실행됩니다.

로그인할 때 로컬 작업 프로세스가 시작됩니다. 기본적으로 5분마다 새 신청과 결제 상태를 읽습니다. 앱 창을 닫아도 자동 동기화는 계속됩니다. 설정에서 자동 동기화를 끌 수 있습니다. Mac이 꺼지거나 잠자기 상태일 때는 처리하지 않습니다.

## 작업 순서

1. **새로고침**으로 접수를 가져온 뒤 유형·진행 단계·검색으로 신청을 찾습니다.
2. 서비스의 결제·심의 상태, 파일과 가사를 확인합니다. 서비스 상태와 이 Mac의 작업 단계는 별도로 표시됩니다.
3. **자료 준비 → 문서 정보 수정**에서 누락된 가사·크레딧을 보완합니다. 트랙이 없는 신청에는 로컬 트랙을 추가할 수 있습니다. 수정은 이 프로그램에만 저장됩니다.
4. 이메일 전달 신청은 수신함에서 파일을 내려받은 뒤 **받은 파일 연결**로 추가합니다. 수신함 자동 조회는 하지 않습니다.
5. **심의 자료 생성**을 누릅니다. 문서를 만들고 서비스 업로드 원본도 내려받습니다. 원본 다운로드만 따로 실행할 수도 있습니다.
6. **자료 준비 → 생성 파일** 또는 **최근 폴더**에서 문서를 열어 확인하고 기관에 제출합니다. **작업 메모**의 체크리스트·진행 단계·마감일·메모로 후속 업무를 관리합니다.

7. **심의 결과**에서 방송사별 **접수예정 · 접수완료 · 적격 · 부적격 · 보완 요청**을 저장합니다. 방송사 전체 상태를 선택하면 해당 방송사의 대상 곡 결과도 함께 바뀌고, 개별 곡을 조정하면 곡별 결과를 기준으로 저장합니다. 여러 방송사를 체크해 같은 상태로 일괄 저장할 수 있습니다. 하나라도 다른 관리자 작업과 충돌하면 전체 저장을 취소합니다. 방송용 MV 적격 결과에는 각 방송사의 연령 등급이 필요합니다. 저장은 이메일을 보내지 않습니다.
8. 온라인 MV는 영등위 등급을 저장하고 필증 PDF·PNG·JPG를 업로드합니다. 등급·필증 저장도 이메일을 보내지 않습니다.
9. 저장을 마친 뒤 상단 **이메일 발송**을 누릅니다. 현재 저장된 전체 신청 방송사의 상태와 미입력 항목, 수신 주소, 제목, 실제 메일 본문을 확인합니다. 이메일의 **전체 심의 현황 확인** 버튼은 기존 고객 결과 페이지로 연결됩니다. 회원은 로그인 후, 비회원은 해당 신청의 전용 조회 링크로 확인합니다.
10. **이 내용으로 이메일 발송**을 눌러 한 번에 안내합니다. 온라인 MV는 등급 이미지·사용법 PDF·필증 세 파일을 첨부하며 자료가 부족하면 발송 대기 사유를 표시합니다. 미리보기 후 결과가 변경되면 최신 내용으로 다시 확인해야 합니다.
11. 발송 이력에서 접수·대기·실패 상태를 확인합니다. 재발송도 미리보기와 명시적 발송을 거쳐야 합니다.

기관 접수 자체는 기관의 업무 화면에서 처리합니다. 이 앱의 로컬 완료 상태는 서비스 결과와 별개입니다. 서비스 결과 저장은 온라인 연결이 필요하며, 웹 관리자와 동시에 수정한 경우 최신 결과를 확인한 뒤 다시 저장하도록 안내합니다. 기존 필증 파일은 새 파일 업로드로 삭제하지 않습니다. 메일의 ‘발송 서버 접수’는 수신함 도착 확인과 다릅니다.

앱 메뉴는 **신청 관리 · 관리자 수동 작업 · 작업 현황 · 데스크 설정**, 온라인 신청 상세는 **신청 정보 · 자료 준비 · 심의 결과 · 작업 메모**로 구성됩니다. 결과 탭은 서비스의 원래 트랙·신청 방송사를 사용합니다. 문서용 로컬 추가 트랙이나 제목 보완은 서비스 결과를 변경하지 않습니다.

## 관리자 수동 작업

이메일·문자 등으로 별도 접수한 신청은 **관리자 수동 작업 → 음반 / 뮤비**에서 관리합니다. 온라인 신청과 자동 매칭하거나 결과·이메일을 전송하지 않으며, 이 Mac에만 저장합니다.

1. **음반** 또는 **뮤비**를 선택하고 Word(`.docx`, `.doc`)·한글(`.hwp`, `.hwpx`) 기준파일을 가져옵니다. 파일당 최대 20MB이며 암호·DRM 보호 파일은 지원하지 않습니다. 뮤비는 온라인 영등위용과 방송용을 선택할 수 있습니다.
2. 추출한 신청 정보·트랙·가사를 확인합니다. 기준파일 원본과 추출 원문은 별도로 보존되며, **자료 준비 → 문서 정보 수정**에서 보완할 수 있습니다. 여러 앨범이 한 파일에 있으면 앨범별로 나누어 가져옵니다.
3. **검토사항**에서 욕설·의심 표현·미번역·별도 번역 대응·연주곡 표시 충돌을 트랙과 행별로 확인합니다. 원문을 자동 삭제하거나 순화하지 않습니다. 검토 표시 후 가사가 바뀌면 다시 확인하도록 표시합니다. 자동 검사가 모든 표현을 판별하는 것은 아니므로 최종 원문 확인이 필요합니다.
4. **심의 자료 생성**은 영어 등 외국어 가사에 한글 번역이 없으면 먼저 온사이드 번역 서비스로 번역해, 이어지는 외국어 줄 묶음 바로 아래에 `(번역: …)` 한 줄로 넣은 뒤 문서를 만듭니다. 미리 보고 싶으면 **미번역 가사 번역**을 먼저 실행할 수 있습니다. 온라인 신청은 생성하지 않습니다. 기존 번역은 그대로 두고, 번역하지 못한 구간(고유명사 등)은 확인사항으로 알립니다. 제공된 별도 번역은 대응 관계를 직접 확인합니다.
5. **받은 파일 연결**로 음원·영상을 보관하고 **심의 자료 생성**을 실행합니다. 음반은 전체 심의서류 DOCX ZIP을 내려받습니다. 뮤비는 건당 처리하며 **가사_아티스트명_제목.doc**와 **영등위·방송 신청 복사붙여넣기 HTML** 두 파일만 생성합니다. 확인사항은 상단 **자료 생성 전에 확인해 주세요**에 표시하고, 생성 당시 정보와 검토 결과는 앱의 생성 이력에 보관합니다.

확인사항이 있어도 자료 생성은 가능합니다. 원문을 보며 보완한 다음 다시 생성하면 이전 생성본과 함께 보관됩니다. 수동 작업의 진행 단계·마감일·체크리스트·메모는 **작업 메모**에서 관리합니다.

2.3 버전은 기존 수동 뮤비 기준파일의 괄호·줄바꿈이 있는 항목명을 다시 읽어 누락된 가수명·감독·주연·줄거리를 복구합니다. 변환 전 관리 데이터를 자동 백업하고, 직접 바꾼 값·원본·이전 생성본은 보존합니다. 생성 자료가 있던 건은 보완된 정보로 다시 생성해 주세요.

2.3.3 버전은 영문 가사 바로 다음 줄의 `(한글 번역)`과 번역 안의 괄호를 인식해 불필요한 재번역을 방지합니다. 기준파일의 반복 가사 셀·다른 표·동명곡·다문단 줄거리·체크박스 읽기를 보완했습니다. 이 파서 변경은 새로 가져오는 기준파일에 적용하며 기존 작업의 입력값을 자동으로 덮어쓰지 않습니다. 새 생성본은 문서 구조와 가사 보존 여부를 검사하고, 뮤비 DOC는 변환 후 다시 열어 본문을 대조합니다. 기준파일 추출 경고도 생성 이력에 함께 남깁니다.

2.4.0 버전은 **사이트 관리** 메뉴를 추가했습니다. 온사이드를 운영하는 Vercel(호스팅)·Supabase(DB·로그인)·Backblaze B2(파일 저장소)·가비아(도메인·DNS)의 상태와 무료 사용량을 한 화면에서 확인합니다. 사이트 응답과 서버 상태 점검, DNS가 Vercel을 가리키는지, SSL·도메인 만료일, Supabase DB·Storage 용량과 이번 달 로그인 회원 수, 메일·예약 작업 실패, 현금영수증 대기, B2 저장 용량(무료 10GB 대비)·종류별 용량·큰 파일·180일 지난 파일·미완료 업로드를 보여줍니다. 무료 한도의 70%를 넘으면 주의, 90%를 넘으면 문제로 표시합니다. Vercel 배포·도메인 연결은 **점검 설정**에 Vercel 토큰을 넣어야 확인하며, 토큰은 데이터 폴더의 `monitor.json`(권한 600)에만 저장되고 백업에는 포함되지 않습니다. 창을 닫아도 10분마다 확인하며 새 문제가 생기면 Mac 알림을 보냅니다. B2 목록 조회는 거래 비용을 아끼기 위해 30분마다(수동 새로고침은 2분 간격) 실행합니다. Vercel Hobby 사용량, Supabase 전송량, B2 결제 수단·한도는 API로 제공되지 않아 각 대시보드 버튼으로 연결합니다. 웹 서버가 Vercel로 옮겨져 필증 업로드는 4MB까지 가능합니다.

2.4.1 버전은 Vercel Pro 사용량을 **사이트 관리**에서 바로 보여줍니다. 이번 결제 주기의 Pro 월 크레딧($20) 사용액, Flat Rate CDN 요청(월 100만 건)·데이터 전송(월 1TB), 크레딧 초과 청구액, 함수 CPU·실행·메모리·전송·빌드의 온사이드 사용량과 팀 전체 사용량을 나란히 표시합니다. 크레딧 75%에서 주의, 100%(초과 청구 시작)에서 문제로 표시하며, 요금 내역은 30분마다(수동 새로고침은 5분 간격) 다시 읽습니다. 사용량은 팀 단위로 집계되므로 Vercel 토큰은 Scope를 팀 ▶ **All Projects**로 만들어야 합니다. 프로젝트 하나만 고른 토큰은 배포·도메인만 확인합니다. 가비아 DNS는 Vercel이 정상으로 인식하는 IP면 정상으로 표시하고, Vercel 권장값이 바뀐 경우에는 "선택" 안내만 보여줍니다.

2.4.2 버전은 데스크 서비스가 업데이트나 재시작으로 다시 켜져도 열려 있던 앱 창이 계속 동작합니다. 접속 토큰을 데이터 폴더의 `session.key`(권한 600)에 보관하기 때문입니다. 연결이 잠시 끊기면 "데스크 서비스에 연결하지 못했습니다"라고 안내하고, 사이트 관리 화면은 10초 뒤 자동으로 다시 확인합니다.

2.5.0 버전은 **저장공간 정리** 메뉴를 추가했습니다. 웹 관리자의 저장공간 정리(`/admin/storage`)와 같은 기준과 같은 서버 처리로, 심의가 끝났거나 환불된 신청에서 고객이 올린 음원·영상·가사·신청서·기타 파일과 보완 제출 파일만 온사이드 저장소(B2)에서 모든 버전까지 영구 삭제합니다. 영등위 필증·연령등급 이미지·표기 가이드·결과 메일 기록과 신청·결제·심의 결과 내역은 유지되고, 고객 화면에는 "보관 종료로 삭제됨"으로 표시됩니다. 목록에서 경과 기간(30·90·180일)으로 거르고 여러 건을 골라 확인 후 삭제하며, 10건씩 나누어 처리합니다. 서비스가 삭제 직전에 대상 여부를 다시 확인하므로 그사이 상태가 바뀐 신청은 삭제하지 않습니다. 삭제 기록은 서비스 진행 이력과 이 Mac의 작업 기록에 남습니다. 이 Mac에 내려받은 원본 파일은 지우지 않습니다. Backblaze 콘솔에서 직접 지우면 이전 버전이 남아 용량이 줄지 않고 서비스 기록과도 어긋나므로, 고객 파일 정리는 이 메뉴나 웹 관리자에서 하세요. 이 기능은 서비스 배포가 함께 필요합니다.

## 목록 삭제와 복원

신청 관리와 관리자 수동 작업에서 **삭제**하면 이 Mac의 **휴지통**으로 이동합니다. 서비스 원본 신청과 보관 파일은 유지하고, 다음 동기화에서도 목록으로 다시 나타나지 않습니다. 휴지통에서 복원할 수 있습니다. 생성·업로드·결과 저장 등이 진행 중이면 완료 후 삭제하세요. 온라인 신청을 복원하면 최신 정보를 다시 불러옵니다.

로컬 Docker의 `onside-doc-qa:local` 변환기가 실행 가능하면 전체 가사 실제 페이지 수를 확인합니다. 3쪽 초과일 때 프롬프트에 따른 문단 조정본을 사용합니다. 변환기를 사용할 수 없으면 원문 줄 구성을 보존하고 인쇄 검수 필요 안내를 남깁니다. 각 신청의 최종 문서는 제출 전에 확인하세요.

## 자동화와 보관

**새 접수 자동 생성**은 기본적으로 꺼져 있습니다. 켜면 첫 동기화 이후 새로 들어오거나 결제 완료로 바뀐 신청의 자료를 생성하고 원본을 다운로드합니다. 첫 실행의 과거 접수 전체를 자동 생성하지 않습니다. 문서 생성은 직렬 처리되며 생성 시점별 사본을 유지합니다. 서비스 원문이 바뀌면 로컬 수정은 유지하고 재확인을 표시합니다.

데이터 위치: `~/Library/Application Support/Onside Review Desk/`

- `신청별 자료/<신청 ID>/`: 원본, 이메일 수신 파일, 생성 이력
- `state.json`: 접수 캐시·로컬 수정·진행·메모·작업 이력
- `자동백업/`: 동기화 성공 시 하루 한 번 관리 데이터 사본
- `백업/`: 설정 화면에서 만든 관리 데이터와 생성 문서 ZIP
- `connection.env`: 서버 전용 연결 키 (다른 사람에게 공유하지 않음)

**관리 백업은 대용량 음원·영상 원본과 연결 키를 제외합니다.** 전체 원본 보관은 Time Machine 또는 위 데이터 폴더 전체를 별도 저장장치에 복사하는 방식으로 수행하세요. 파일과 폴더는 현재 Mac 사용자만 읽도록 생성합니다. 로컬 서비스는 `127.0.0.1:43127`에서만 수신합니다.

## 복구와 종료

관리 데이터 복원은 먼저 아래 명령으로 작업 프로세스를 정지한 뒤 기존 `state.json`을 다른 이름으로 보존하고, 자동백업 JSON 또는 백업 ZIP의 `state.json`을 데이터 폴더에 복사합니다. ZIP에 포함된 `신청별 자료`도 같은 위치로 복사합니다. `connection.env`는 보존하세요. 이후 시작 명령을 실행합니다.

```sh
# 로컬 프로세스 정지
launchctl bootout gui/$(id -u)/kr.onside.review-desk
# 다시 시작
launchctl bootstrap gui/$(id -u) "$HOME/Library/LaunchAgents/kr.onside.review-desk.plist"
```

완전히 제거하려면 작업 프로세스를 정지한 뒤 `~/Library/LaunchAgents/kr.onside.review-desk.plist`, 앱 및 바탕화면 바로가기를 제거합니다. 자료 폴더는 보관 여부를 직접 결정한 후 삭제하세요. 앱 제거가 온사이드 서비스에는 영향을 주지 않습니다.

## 개발과 검증

```sh
node --import tsx --test tools/onside-desk/source.test.mjs tools/onside-desk/tests/*.test.mjs
node tools/onside-desk/build-mac.mjs
node tools/onside-desk/install-mac.mjs
```

설치 스크립트는 앱과 로그인 작업을 설치하고 `.env.local`에서 필요한 Supabase/B2 키만 `0600` 설정 파일에 복사합니다. 기존 연결 키를 보존하고 서비스 주소와 관리자 식별자를 추가합니다. 관리자가 한 명인 경우 해당 계정을 확인해 연결하며, 여러 명이면 설치 시 관리자 ID를 지정해야 합니다. 결과 저장 요청은 기존 서버 전용 키에서 파생한 서명으로 인증하며 브라우저 화면에 키를 노출하지 않습니다. 빌드에는 체크섬을 확인한 공식 Node 24.7.0 arm64 런타임 tarball이 필요합니다. `build-mac.mjs`는 앱 서명을 로컬 ad-hoc으로 작성하며 App Store 배포용 서명이 아닙니다.
