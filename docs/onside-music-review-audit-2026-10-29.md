# 내 음악 관리 심의 내역 점검 (2026-10-29)

온사이드 결과는 소유자와 정확한 신청·음원 범위를 유지한 채 원본에서 조회한다. 관리자가 방송사 결과를 변경해도 음악 관리 자료의 버전은 증가하지 않으므로, 불러오기 작업이 끝난 뒤에도 화면 복귀 시와 화면이 보이는 동안 30초 간격으로 다시 조회하도록 수정했다. 진행 중인 불러오기는 기존 5초 간격을 유지한다.

관리 화면과 동일한 방송사 결과 판정 함수를 사용해 전체 방송사의 결과가 확정되면 음악 관리에도 완료 상태를 표시한다. 대기·보완 요청이 남아 있으면 신청 전체 상태만으로 완료 처리하지 않는다. 방송사 결과와 곡별 적격·부적격 내용은 원본 결과 화면에서 확인하며 사용자 직접 입력 기록으로 복제하지 않는다.

직접 입력 방송사 목록에서 EBS, tvN, JTBC, G1을 제외했다. 기존 기록을 수정할 때도 제외된 방송사가 다시 선택 항목에 나타나지 않도록 했다. 과거 기록과 공식 로고 파일은 보존한다.

## 직접 저장 오류 조사 상태

사용자가 알려준 `Whispers in the Dark`는 조회가 정상이며, 직접 입력을 적용한 자료는 약 71KB, 감사 자료는 약 238바이트로 용량 제한에 걸리지 않는다. 실제 서버 조회 함수와 변경된 심의 결과 조회 쿼리를 운영에서 읽기 전용으로 확인했다. 점검 시 해당 앨범에 연결된 온사이드 신청은 없었고 직접 입력 기록도 없었다.

신고된 일반 DB 오류의 구체적인 원인은 재현하지 못했다. 운영 자료의 쓰기 경로를 이용한 검증은 자동 승인 검토에서 거부되어 실행하지 않았으며, 격리 PostgreSQL 테스트로 대체했다. 이후 발생하는 오류를 구분할 수 있도록 조회·저장 구간, 제한된 오류 코드와 오류 종류만 로그에 남긴다. SQL, 원문 오류, 계정 식별자, 저장 내용, 자격 증명은 기록하지 않는다.

후속 확인: 사용자에게 재저장이 정상 동작한다는 확인을 받았다. 운영 읽기 전용 재조회에서도 해당 음원의 선택 항목 16개가 모두 `eligible`로 저장되고 자료 버전이 87로 증가한 것을 확인했다. 별도의 로컬 PostgreSQL·PostgREST 환경에서 해당 앨범 복제 자료로 실제 서버 코드와 Supabase SDK를 통한 저장·수정·재조회도 통과했다. 원인은 미확정이며 현재 정상 저장·재조회 상태임을 확인한 것으로 기록한다.
