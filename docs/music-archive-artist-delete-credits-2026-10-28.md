# 아티스트 삭제와 곡별 저작자 자동 입력

2026-10-28 KST. 회원 요청에 따라 아티스트 목록에 삭제 기능을 추가하고, 멜론·지니에서 불러온 곡의 작사·작곡·편곡 정보를 자동으로 채운다.

## 동작

- 아티스트 카드의 삭제 버튼에서 이름과 앨범 수를 확인한 뒤 목록에서 제거한다. 기존 소유자·버전 검사를 거치는 보관 처리이며 음악 자료와 심의 신청·결과는 보존한다. 진행 중인 수집은 중단한다. 삭제 저장 후 작업 취소 요청만 실패했을 때도 성공한 삭제를 실패로 표시하지 않는다. 이후 복구·재시작된 작업은 늦게 도착한 취소 요청의 대상에서 제외한다.
- 멜론·지니 수집은 전체 앨범과 수록곡을 먼저 저장한 뒤, 공식 앨범에 열거된 곡 ID로 저작자를 조회한다. 앨범 한 페이지 또는 곡 한 페이지를 작업 한 단계로 처리하고 커서를 저장한다. 저작자 조회 실패가 저장된 앨범을 없애지 않으며 같은 곡부터 재시도할 수 있다. 기존 v1 진행 커서와 완료 처리를 유지한다.
- 공개 응답에서 작사·작곡·편곡 이름만 추출한다. 앨범 ID와 곡 ID가 모두 일치하는 항목에 연결하며, 동명 곡이나 저작자 이름만으로 연결하지 않는다. 같은 사람의 여러 역할, 여러 저작자와 기존 역할별 정보 및 회원이 수정한 저작자 정보를 보존한다. 가사나 회원의 비공개 수정·심의 크레딧을 공개 원본 저장소에 넣지 않는다.
- 전체 수록곡과 저작권 탭에서 참여 앨범의 비관리 곡도 저작자 정보를 읽을 수 있다. 기존 관리 대상·심의 신청·등록 입력 범위는 유지한다. 공개 저작자 이름을 협회 등록 완료나 회원의 권리 소유 확인으로 표시하지 않는다. 협회 정보는 기존 공식 조회 링크와 확인된 작품번호 입력 경로를 유지한다.
- 수집 중에는 앨범 수집과 저작자 수집을 구분해 안내하고, 저작자 단계에서 실패하면 저장된 앨범은 유지됐음을 표시한다. 고객 응답에 원본 커서·내부 오류·회원 ID를 노출하지 않는다.

공식 페이지는 정해진 URL·요청 시간·응답 크기 제한과 기존 제공처 공용 호출 간격을 적용한다. 수동 저작자 재조회도 같은 호출 간격을 사용한다. DB 스키마와 외부 API 키 변경은 없으며 Spotify·YouTube 키 설정 보류는 유지한다.

## 검증

- 음악 관리·멜론·지니 검사 217개 통과. 실제 작업 실행 경로를 모의 HTTP/저장소와 함께 실행해 앨범 저장, 저작자 원본 저장 및 원자적 반영, 실패 후 동일 곡 재개, 수동 저작자 보존, 수집 중 아티스트 삭제를 확인했다.
- 실제 멜론 곡 600865299와 지니 곡 113373802의 작사·작곡·편곡 5개 역할 항목이 일치한다. 멜론 참여곡 600186810에서도 16개 역할 항목을 파싱하고 기존 비관리 범위를 유지한 채 작품에 연결했다. 회귀 fixture에는 공개 메타데이터 발췌만 포함한다.
- 삭제의 소유자·버전 검사, 대상 작업만 취소, 취소 요청 실패 및 동시 복구 보호를 서비스 검사로 확인했다. 실제 운영 아티스트를 검증용으로 삭제하지 않는다.
- 회원 화면 브라우저 검사 36개 통과. 삭제 취소·실패·버전 충돌·모바일 확인창, 참여 곡의 역할별 저작자 표시, 심의 범위 보존, 저작자 수집 진행·부분 실패·완료 상태 전환을 확인했다.
- TypeScript, 변경 파일 ESLint와 diff 검사 통과. `HEAD` 격리본에 이번 코드·테스트 20개 파일만 반영한 `npm run build -- --webpack`도 통과했으며, 정적 페이지 87개 생성 및 모든 반영 파일의 원본 해시 일치를 확인했다.

배포는 이번 음악 관리 코드·테스트·기록만 포함한다. 별도 심의 문서와 Mac 앱 미커밋 작업은 보존한다. 배포 후 이미 저장된 빈티지코드 라이브러리의 정상 동기화 경로를 실행해 기존 앨범에 저작자 정보를 채우고 실제 저장 결과를 확인한다. 새 `credits` 커서를 읽지 못하는 이전 코드로 롤백하면 해당 진행 작업은 보존되지만 수정 버전에서 재개해야 한다.
