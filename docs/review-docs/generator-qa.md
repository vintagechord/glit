# 심의자료 생성기 검증 기록

검증일: 2026-09-07. 고객 원본이나 운영 DB 대신 저장소의 합성 fixture를 사용했다.

## 재사용과 출력

`src/lib/admin/review-docs.ts`의 기존 `buildReviewDocsZip`에서 렌더·ZIP 단계를
`renderPreparedReviewDocuments`로 분리했다. 기존 신청 다운로드와 새 독립 관리자
`generateReviewDocuments(data)`가 같은 DOCX 템플릿, `renderReviewDocTemplate`,
`yazl` ZIP 처리를 사용한다. 새 API는 원격 수집·번역·DB 저장을 하지 않는다.

단일 앨범 2트랙: DOCX 9개. 다중 앨범 2개/총 3트랙: DOCX 14개.
통합신청서는 TBS/WBS/PBC 각각 1개이며, 앨범 수 × 4 + 전체 트랙 수 + 3을 검사한다.
영등위 1곡과 2곡은 각각 DOCX 1개와 2개만 반환하며 ZIP 외에 개별 파일 버퍼를
제공한다. 영등위 출력에 담당자·연락처·회사·크레딧·신청서는 포함하지 않는다.

## 실행한 검사

```sh
node --import tsx --test tests/review-docs-docx.test.ts tests/review-docs-normalized.test.ts
node scripts/validate-review-doc-templates.mjs
node --import tsx scripts/review-docs-render-fixtures.ts
```

기존 테스트 6개는 변경 전에 모두 통과했다. 변경 후 기존 6개와 새 11개를 합쳐
17개가 통과했다. 빈 가사와 작사자 공백을 자동으로 Inst. 처리하던 기존 테스트는
요청된 안전한 판정 규칙에 맞게 변경했다. 관련 파일 ESLint도 통과했다.

검증 범위는 다중 앨범, 긴 앨범명·회사명·가사, 한글·영어·일본어·혼합 가사,
반복 구간의 번역 보존, 더블 타이틀, 4개 타이틀의 WBS 수동 선택, 타이틀 미지정,
확인된 Inst./MR, `Mr. Sunshine`, 누락 가사·번역 차단, 불확정 날짜 원문 유지,
Unicode 파일명과 충돌, MV 최소 입력, 누락·손상 템플릿, 회사명 외 출력 동일성,
표 구조, ZIP 파일 수·CRC이다.

추가로 재추출 병합 테스트 9개와 실연자 계약 테스트 3개도 통과했다. 실패한 원본·가사만
재수집 대상으로 고르고, 관리자가 수정하거나 명시적으로 비워 둔 값은 보존한다.
재추출 근거를 갱신하며 확실하지 않은 앨범·곡 연결은 검토 오류로 남긴다.
기존 접수 출력의 실연자 기본값과 새 독립 도구의 누락 실연자 빈칸을 실제 DOCX 셀로 확인했다.

런타임에는 구성 XML, 필수 곡명과 전체 가사, 반복 행 수, 미치환 필수 태그,
플로팅 표·고정 행 높이, DOCX 파일 수, 중복 경로, ZIP CRC를 검사한다.
템플릿 내용의 SHA-256을 결과에 기록하며, 구조 검사와 실제 렌더링은 구분한다.
`validation.rendered`는 `false`로 반환하므로 UI에서 육안 검수 완료로 표시하면 안 된다.

## 실제 렌더링 검수

합성 출력 DOCX 16개를 번들 `render_docx.py`와 번들 LibreOffice로 PDF·PNG로
렌더링했다. 전체 29페이지를 각각 열어 확인했다. 페이지별 텍스트 추출로도 완전히
비어 있는 페이지가 없음을 확인했다. 결과는 로컬 `tmp/review-docs-qa/final-rendered`
아래에 있고, 실제 제출 ZIP에는 PDF/PNG를 포함하지 않는다.

| 출력 | 문서 수 | 페이지 수 |
| --- | ---: | ---: |
| 가요심의요청서 | 2 | 2 |
| 심의폼 및 앨범정보 | 4 | 14 |
| 가사전체파일 | 2 | 3 |
| 곡별 개별 가사 | 3 | 5 |
| 방송국 통합신청서 | 3 | 3 |
| 영등위 전용 가사 | 2 | 2 |
| 합계 | 16 | 29 |

담당자 표와 앨범정보 표 겹침, 셀 침범, 가사 잘림, 표의 페이지 밖 이탈은 발견되지
않았다. 긴 가사 62절이 모두 이어지고, 다음 곡의 제목·크레딧·가사가 함께 배치됐다.
심의폼의 기존 곡별 페이지 나눔과 표 구조를 보존했으므로 긴 가사의 마지막 페이지와
짧은 곡의 페이지에는 여백이 남을 수 있다. 글자 크기를 줄이지 않았다.

검수 중 가사 문단의 기본 양쪽 정렬 때문에 강제 줄바꿈마다 단어 간격이 크게
벌어지는 현상을 발견했다. 가사 문단만 왼쪽 정렬·격자 맞춤 해제로 수정한 뒤
16개 문서를 다시 렌더링하고 최종 29페이지를 모두 재검수했다.

기존 방송국 템플릿과 가요심의요청서는 변경하지 않았다. 심의폼은 11pt, 가사 행의
페이지 분할, 가사 문단 정렬·줄간격만 조절했다. 가사 템플릿은 지정된 글자 크기,
1.15 줄간격, 제목/크레딧 붙임 및 다음 곡 앞 여백을 적용했다. 기존 표의 너비·열·병합과
담당자 표의 위치는 기존 구조 테스트로 확인했다. 고객 업로드 파일을 양식으로 사용하지 않았다.

## 확인 한계

로컬 번들 LibreOffice의 기본 Fontconfig가 한국어 글꼴을 찾지 못해 최초 렌더의
한글이 보이지 않았다. 로컬 QA 전용 Fontconfig에 macOS의 Apple SD Gothic Neo 및
Arial Unicode MS를 지정해 해결했다. DOCX 내부의 `맑은 고딕` 지정은 보존했고,
위 육안 검수는 **대체 글꼴을 사용한 LibreOffice 결과**이다. Windows Word와 실제
맑은 고딕 설치 환경의 페이지 수·줄바꿈까지 검증했다고 볼 수 없다. 운영 반영 전
최종 제출 환경에서 추가 확인해야 한다.

템플릿 버전 변경 시 이 fixture를 다시 생성·렌더링해야 한다. 이 검증은 양식의
실제 방송국 접수 유효성이나 영등위 심의 결과를 판정하지 않는다. 운영 배포와
운영 마이그레이션은 실행하지 않았다.
