## 결론

## 실제 QA 결과 전달 검증

실제 방송사 접수나 고객 자료와 구분하기 위해 **QA ONLY** 표시의 신청 1건을 공개 초안 API로 만들었다. 식별 prefix는 `0FE4EAA1`이다. 전체 신청 ID, 조회 토큰, signed URL은 공개 문서에 기록하지 않는다.

관리자 실제 화면에서 QA 제목·메모를 저장하고 `onside-QA-ONLY-not-a-review-certificate.pdf`를 업로드했다. 파일 크기는 **2,072바이트**이며, 실제 심의 필증을 대신하는 자료가 아니다. 관리자 등급 공개 동작도 확인했다.

|---|---|
| 업로드 완료·등급 공개 전 소유자 다운로드 | HTTP 403 — 공개 전 파일 차단 |
| 등급 공개 후 소유자 조회 토큰 다운로드 | HTTP 200, PDF 서명·Content-Type·attachment 응답 확인 |

저장 상태는 `status=RESULT_READY`, `payment_status=UNPAID`, `amount_krw=0`, `result_status=APPROVED`, `result_notified_at=null`이었다. 금액이 0원이라는 이유로 PAID 처리하거나 실제 거래를 만든 것이 아니다. 실제 Chrome 시크릿 비회원 화면은 미결제 상태에 맞게 **입금 확인 대기**로 표시됐다.

이 검증은 운영 앱·B2를 통한 QA 파일 전달과 공개/접근 제어의 증거다. **PG 결제 완료 → 고객 화면 다운로드 버튼 → 실제 최종 결과 수령**의 전체 흐름은 사용자의 결제 시험 후 추가 확인이 필요하다. QA 자료를 실제 고객 결과나 실제 방송사 심의 완료로 집계하지 않는다.

공개 가능한 집계는 [운영 검증 증거 요약](onside-production-evidence-2026-10-24.json)에 있다. 비공개 원본 근거는 `/private/tmp/onside-delivery-qa-20261024/`의 검증 JSON과 `/private/tmp/onside-production-api-checks.json`에 있다. `submission-private.json`에는 조회 토큰이 있으므로 공개·커밋·외부 전달하지 않는다. QA 신청과 파일은 삭제 완료를 검증한 항목이 아니므로 정리가 필요할 때 식별된 이 QA 범위만 확인한다.

## 반영한 DB 변경과 복구 자료

다음 4개 파일의 SQL과 migration 이력을 같은 트랜잭션에 기록했다. 기존 함수 정의 MD5와 migration 105개를 실행 전 검사했고, 실행 중 오류가 발생하면 전체가 rollback되도록 구성했다.

1. `20261023210008_submission_supplements.sql`
2. `20261023212202_payment_pre_review.sql`
3. `20261023212253_certificate_result_history.sql`
4. `20261024015746_review_documents_admin_retention.sql`

변경 전 결제 함수 3개의 실제 본문은 기존 로컬 0076/0097과 동일했다. 현재 진행 중인 문서 작업 0건, 만료됐지만 미정리인 작업 0건, 보관 기한 갱신 대상 0건을 사전 확인했다. migration 사전 점검에서는 고객 행을 조회하거나 원본 파일을 삭제하지 않았다. 이후 전달 검증은 별도로 만든 QA 신청에 한정했다.

변경 전 함수·migration 버전·이전 만료 기본값을 CSV로 내려받았다. 원본은 로컬 Downloads의 `Supabase Snippet Untitled query.csv`, 가공 사본은 `/private/tmp/onside-production-backup-20261024.json`이다. 가공 사본 SHA256은 `cf973adc020fff3d410aa1a1af4c796e4400c73dad8d8eb2e229e7692b387315`다. 이는 변경한 정의의 복구 자료이며 전체 고객 DB/스토리지 백업이라고 주장하지 않는다.

복구 SQL `/private/tmp/onside-production-function-rollback-20261024.sql`은 기존 함수 3개와 작업 만료 기본값을 복구하는 범위다. 신규 보완·필증 이력 테이블을 삭제하거나 고객·결제 기록을 되돌리는 용도가 아니다. 코드 rollback 시 구버전 worker의 7일/90일 자동 정리가 재개되지 않도록 확인해야 한다.

## 이메일·도메인 보류 상태

사용자가 도메인 구매·이메일 연동을 나중으로 미루도록 지시했다. 현재 운영 배포는 자동 이메일 없이 직접 조회와 고객센터 안내를 사용하는 수동 모드다. 신규 비밀번호 복구 메일·조회 코드 이메일 요청은 고객센터로 안내하며, 기존 정상 복구 링크 처리와 직접 조회는 유지한다. 관리자 결과 저장과 자동메일 보류를 실제 발송 완료와 구분한다.

[Resend 공식 무료 플랜 안내](https://resend.com/changelog/three-domains-on-the-free-tier)는 인증 도메인 3개를 지원한다. 계정의 기존 인증 도메인은 아트멜론용이므로 온사이드 발신에 사용하지 않았다. 다른 서비스 발신 설정이나 키를 온사이드에 적용하지 않는다.

기존 `onside17.com`의 `notify` 발신 도메인을 Resend에 준비했으나, 가비아 DNS 관리툴은 이 도메인을 퍼스트몰 고객센터를 통해 변경하도록 제한했다. DNS 레코드 저장은 실행하지 않았다. `mail.onside17.com`은 기존 Hiworks CNAME이므로 변경하지 않았다. 준비한 `notify.onside17.com`은 인증 대기 상태의 미사용 항목이며 온사이드 발신 주소로 설정하지 않았다.

도메인·메일·호스팅 유료 플랜 신청이나 결제는 하지 않았다. 향후 사용자가 도메인 연동을 재개하면 온사이드 전용 인증 도메인·발신 주소·키 범위를 확인하고, transactional 모드로 전환해 재빌드한 뒤 지정 수신자의 실제 수신을 별도 검증한다. 이메일 연동은 사용자 지시로 보류했으며, 카카오는 미설정 상태여서 실제 수신을 검증하지 않았다.

## 결제·환불 검토와 사용자 시험 인계

- 금액은 서버 상품/주문 데이터에서 계산한다. 카드창 인증 성공과 최종 승인 성공은 별개다.
- 승인 claim, 금액·소유권 검사, 결제 snapshot 및 불확실 승인 잠금을 유지했다. 운영 함수는 초기 결제 상태만 `PRE_REVIEW`로 전환하며 기존 진행·결과·완료 상태와 재콜백 상태를 유지한다.
- 모바일 카드는 기존 서버 차단을 유지한다. 실제 카드 시험은 PC를 사용하고, 모바일은 무통장 안내를 확인한다.
- 사용자 시험은 시험용 표시 신청 1건으로 진행하고, 주문번호·TID·금액을 PG 거래, 앱 주문/신청 상태, 관리자 결제 목록과 대조한다. `/admin/payments?filter=attention`의 불확실 거래는 재결제 전에 PG 기록을 확인한다.
- **심의 주문의 실제 PG 환불 API와 취소 결과의 앱 자동 동기화는 구현돼 있지 않다.** `requestRefund` 호출은 다른 구독 상품 경로에만 있으며 심의 취소 시험의 대체 경로가 아니다.
- 관리자 화면의 `REFUNDED` 표시만으로 실제 환불 성공을 판정하지 않는다. 주문에 연결된 개별 신청의 결제 상태 수정은 차단된다. PG 관리자 전액 취소 결과와 주문 전체 상태·처리 이력을 대조하고 반영하는 운영 절차도 아직 확정되지 않았다.
- 사용자의 직접 승인·환불 시험과 결제 후 고객 결과 UI 확인이 남아 있다. 에이전트의 실제 PG 승인·취소는 0건이다.

## 보관 정책의 구현 범위

음원 보관 기간은 **각 파일의 제출일부터 1개월**로 확정했다. 보완 음원도 그 파일의 제출일을 적용한다. **음원 자동 삭제 job은 아직 구현하지 않았다.** 기존 분류에는 신청서·ZIP도 AUDIO로 저장될 수 있으므로 이 값만으로 삭제하면 안 된다. 실제 음원 분류와 제출 시각·삭제 이력·이메일/백업/객체 버전 처리를 포함하는 구현이 필요하다.

영상·가사·신청서·결과 파일·필증과 신청·심의 결과 내역은 관리자 삭제 전까지 보관한다. 관리자 서류 변환의 7일 객체 삭제·90일 이력 삭제를 중지하고 새 작업과 아직 유효한 미정리 작업을 무기한으로 전환하는 변경은 운영에 반영했다. 이미 만료·삭제된 자료를 복원하는 변경은 아니다.

## 배포 전 검사와 남은 업무

전체 단위 **852개 중 846 PASS / 0 FAIL / 6 환경 의존 SKIP**, manual 모드 프로덕션 Webpack 빌드·타입 검사 PASS, ESLint **0 errors / 기존 9 warnings**. 기존 인증 17개와 manual 한국어·영어 4개 브라우저 회귀 PASS. 필증 다운로드 우회 수정의 신규 5개와 기존 필증 이력 3개 회귀도 PASS다. 실제 Render Docker 빌드·운영 배포 성공은 별도로 확인했다.

이 검사와 QA 파일 전달은 실제 PG 거래·알림 수신·결제 후 모든 고객 UI 완료의 대체 증거가 아니다. 남은 업무는 사용자 직접 결제·환불 시험과 PG/앱 대조, 결제 후 결과 버튼 확인, 심의 환불 상태 동기화·운영 절차 확정, 추후 전용 도메인/메일 연동과 실제 수신 검증, 음원 1개월 삭제 자동화다.
