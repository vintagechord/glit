# 앨범 불러오기 저장 오류 복구

2026-10-28 KST. 통합 검색·멜론 목록 수집 배포 후에도 회원의 빈티지코드 라이브러리는 앨범 0개였으며, 멜론과 지니 작업 모두 첫 앨범 저장 직전에 `DATABASE_ERROR`로 중단됐다. 이전 공개 페이지 수집 검사는 실제 회원 DB 저장 경로를 포함하지 않아 이 문제를 발견하지 못했다.

## 원인과 수정

수집 작업은 앨범을 저장하기 전에 해당 회원의 심의 자료에서 크레딧을 조회한다. 이 조회가 PostgreSQL `submission_status` enum에 없는 `CANCELLED`를 제외 조건에 넣어 `22P02` 오류를 발생시켰다. 조건에 맞는 심의 자료가 0개여도 조회 자체가 거부됐다. 실제 운영 DB의 동일 조회에서 오류를 재현했고, 제외 조건을 유효한 `DRAFT`, `PRE_REVIEW`로 고친 조회는 정상 응답했다.

회원 소유권·삭제 자료 제외 조건은 유지한다. JS의 과거 상태값 방어 처리는 그대로 두며, DB enum이나 기존 자료를 변경하지 않는다. 아티스트 추가 시 별도로 남기던 영구 진행 문구도 제거해, 실제 백그라운드 작업 상태가 완료·부분 실패로 바뀌면 “앨범을 불러오고 있습니다.” 안내가 사라지게 한다.

## 검증 범위

- 실제 `runArchiveJob`을 통해 제공처 요청·응답 파싱, 병합, 크레딧 조회, 공개 원본 저장, 원자적 라이브러리 반영까지 실행하는 회귀 검사를 추가했다. 외부 HTTP와 저장소만 대체하고 DB fixture는 빈 결과에서도 enum 상수를 먼저 검증한다.
- 멜론·지니의 첫 앨범 저장과 완료, 회원별 크레딧 격리, 공개 원본에 비공개 크레딧 미포함, 중간 저장 실패 후 체크포인트 유지·오류 정보 가림·재개·회원 수정 보존을 확인한다.
- 실제 화면의 주기적 조회로 대기 중 작업이 부분 실패 또는 완료가 됐을 때 진행 문구·재시도 버튼·앨범 표시가 함께 갱신되는 브라우저 회귀 검사 2개를 추가했다.
- `node --test --import tsx tests/music-archive*.test.ts`: 180개 통과. 위 신규 작업 실행 회귀 검사 4개를 포함한다. 브라우저 회귀 검사 2개, TypeScript, 변경 파일 ESLint, `git diff --check`도 통과했다.
- `HEAD`를 푼 격리본에 이번 코드·테스트 4개 파일만 덮어쓴 뒤 `npm run build -- --webpack` 통과. 정적 페이지 87개를 생성했고, 검증한 파일과 배포할 파일의 해시를 대조했다.

사용자가 승인한 음악 관리 수정·운영 반영 범위의 후속 장애 수정이다. Spotify·YouTube 키 설정은 계속 보류한다. 별도 진행 중인 심의 문서·Mac 앱 변경은 포함하지 않는다. 배포 후 중단된 해당 라이브러리의 기존 두 작업을 정상 재개 경로로 이어서 실행하고, 운영 DB에 저장된 결과를 확인한다.
