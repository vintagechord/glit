# 심의데스크 기준파일 분석 및 문서 생성 점검

2026-10-28 심의자료·가사지 생성 오류 신고를 점검하고 Mac 심의데스크 2.3.3/build 8에 반영했다. 기존 양식 파일은 변경하지 않았다.

## 리코 사례

사용자가 지정한 리코(Ricoe) - Luv Ur Mind는 로컬 휴지통에 남아 있었다. 기록된 위치의 HWP 원본과 이전 생성 DOC는 없었으며, 백업 ZIP에서도 해당 원본을 찾지 못했다. 따라서 원래 HWP의 지면과 이전 DOC의 열기 오류는 직접 재현하지 못했다.

보존된 추출 원문과 저장 가사는 1,741자·85행이 일치했다. 바탕화면의 기존 DOCX에도 공백을 정규화한 같은 가사가 있었다. 다음 줄의 `(한글 번역)`을 번역으로 인정하지 않아 28개 영문 행을 미번역으로 표시하는 오류를 재현했다. 중첩 괄호를 포함한 번역 대응을 고친 뒤 미번역 표시와 번역 요청 대상이 0개가 되고 원문은 동일함을 확인했다. 번역 서비스 호출은 하지 않았다.

저장된 내용의 사본으로 DOC를 다시 생성해 본문 보존 및 2페이지 출력을 확인했다. 기존 DOCX는 같은 렌더러에서 4페이지였다. 이 페이지 수 차이는 가사 누락이 아니라 양식과 간격의 차이다. 휴지통 항목을 복원하거나 고객 입력·기존 생성 이력을 변경하지 않았다.

## 수정 내용

- 공유 추출기: 반복 가사·번역 셀의 뒤쪽 보존, 표 경계마다 열 구성을 초기화, 동명곡의 트랙번호 구분, 중복 타이틀 표시 처리.
- DOCX 읽기: 대체 텍스트박스 중복, 콘텐츠 컨트롤 내부 행·셀 누락, 이동 전 텍스트 중복, 빈 문단 소실을 수정. 머리글·바닥글·각주는 원문 근거에 보관하고 마지막 곡 가사에 붙이지 않음.
- 수동 가져오기: 체크박스의 앞/뒤 위치 지원, 미선택 값 경고, 다문단 줄거리와 가사 분리, 빈 항목 뒤의 다른 항목 보존, HWPX 가사 절 사이 빈 줄 보존.
- 문서 생성: 줄바꿈·Unicode 정규화, DOCX ZIP/XML·필수 입력 위치·곡명 및 가사 출력 검사. MV DOC는 변환 후 다시 열어 아티스트·곡명·전체 가사를 대조.
- 파일명: 생성 파일과 ZIP 내부의 각 경로 요소를 240 UTF-8 바이트 안으로 제한. 긴 이름은 해시와 확장자를 유지하고 본문은 줄이지 않음.
- 추출 경고를 문서 생성 당시 경고·이력에 보존. 신규 수동 가져오기는 parserVersion 4, 가사 검토 해시는 version 3.

## 검증 및 적용 범위

- 데스크 및 심의자료 회귀: 196개 중 191개 통과, 5개 건너뜀. 건너뛴 항목은 Linux 전용 프로세스/메모리 검사 2개와 고정 Python/OCR 환경이 필요한 검사 3개다.
- 관리자 수동 작업 브라우저 검사 24항목 통과. 실제 신청이나 외부 결과·메일을 생성하지 않는 합성 화면 검사다.
- TypeScript 및 변경 TypeScript 파일 ESLint 통과. 문서 검증기의 중복 타이틀 표시 오거부도 독립 리뷰에서 찾아 회귀 검사에 포함했다.
- 기존 로컬 `onside-doc-qa:local` 컨테이너를 네트워크 차단 상태로 사용하여 21개 문서의 44페이지를 렌더링하고 검수했다. 원본 글꼴이 없는 환경의 대체 글꼴을 사용하므로 실제 Word·한컴의 페이지 수는 달라질 수 있다.
- Mac 앱 서명, 로컬 `/health` 버전, 네이티브 화면의 v2.3.3, 설치 소스 해시를 확인했다. 설치 전 관리 데이터 백업과 이전 앱 보관을 수행했고 기존 2개 작업(휴지통 포함), 존재하던 파일 5개, 연결키를 보존했다. 설치 근거는 `tools/onside-desk/qa/install-verification-20261028.json`이다.

이 변경은 설치된 Mac 앱에 적용했다. 웹에서도 쓰는 공유 추출기 소스와 테스트는 함께 수정했으며 이번 작업에서 운영 웹을 별도로 배포하지 않았다. Spotify·YouTube 키 설정은 수행하지 않았다.
