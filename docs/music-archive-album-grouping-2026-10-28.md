# 같은 발매작의 중복 표시 방지

2026-10-28 KST. 멜론과 지니에서 같은 앨범을 각각 가져오면 회원의 내 음악 관리에 두 카드가 나타나는 문제를 수정한다. 아티스트 목록의 앨범 수, 앨범 목록, 검색, 상세 화면에서 같은 발매작을 하나로 표시한다.

## 판별과 보존

서로 다른 제공처의 공식 링크를 가진 항목에서 앨범명, 정확한 발매일, 가수명, 버전, 수록곡 수와 디스크·곡 순서를 함께 비교한다. 수록곡의 제목과 확인된 녹음 식별자가 모순되지 않아야 한다. 제목에 포함된 참여자 표기의 제한적인 차이만 정규화하며, 다른 날짜·편집본·라이브·리마스터·모호한 다중 후보는 자동으로 합치지 않는다.

저장된 원본 앨범·곡·작품·심의 연결은 삭제하거나 재작성하지 않는다. 화면에서만 검증된 항목을 묶고 실제 원본 ID를 대표 ID로 사용한다. 같은 곡의 서비스 링크와 저작자 정보를 함께 표시하고, 각 원본에 저장한 업무 이력을 보존한다. 관리 대상으로 확인된 곡만 신청·등록 입력 대상이 된다. 기존 앨범·곡 주소도 같은 상세 화면으로 연결한다.

공식 페이지가 곡명을 `재생 불가`로 표시하는 예외는 다른 모든 곡과 앨범 정보가 일치할 때 앨범만 묶는다. 해당 곡은 다른 원본 곡과 동일하다고 단정하지 않고 별도 항목으로 유지하며 저작자나 심의 완료 상태를 옮기지 않는다.

자동 수집은 기존 제공처별 ID로 갱신한다. 목록을 읽을 때 같은 판별을 적용하므로 다시 불러오거나 새로고침해도 동일 발매작의 카드가 늘어나지 않는다. 아티스트 목록은 최근 12개 미리보기와 별도로 전체 발매작의 판별에 필요한 필드만 소유자 범위에서 조회해 앨범 수를 계산한다.

새 심의 신청은 검증된 같은 곡을 한 번만 선택한다. 이미 저장된 신청의 곡 ID와 순서는 유지하며, 원래 신청하지 않은 곡으로 심의 범위를 넓히지 않는다. 저작자 재조회는 묶인 앨범의 각 제공처 원본을 대상으로 진행한다.

DB 스키마, 외부 API 키, 기존 보관·복구 및 회원 소유권 검사는 변경하지 않는다. Spotify·YouTube 키 설정 보류도 유지한다.

## 확인 대상

빈티지코드는 제공처 원본 26개 가운데 같은 발매작 12쌍을 묶으면 **14개 앨범**이다. 원본 108개 수록곡과 97개 작품은 그대로 보존하며, 동일성이 확인되지 않은 `재생 불가` 2개 항목도 삭제하지 않는다. 제공처별 원본 수는 고유 음원 수를 뜻하지 않는다.

## 검증

- 음악 관리·멜론·지니 검사 **252개 통과**. 공식 공개 메타데이터 fixture의 26개→14개 판별, 날짜·버전·가수·곡 순서의 충돌, 모호한 후보, 제공처 재수집, 원본 불변성을 확인했다.
- 회원 화면 검사 **40개 통과**. 한 앨범·한 곡 표시, 원본별 저작자 결합, 과거 주소, 기존 기록 수정, 제목 수정과 직접 곡 추가 후 그룹 유지, 반복 새로고침, 아티스트 삭제와 참여곡 범위를 확인했다. 모바일 화면도 확인했다.
- 같은 녹음 ID를 참조하는 서로 다른 곡은 표시용 저작자 목록을 곡별로 분리한다. 이 표시용 정보는 원본 편집기나 저장 명령에 사용하지 않는다. 그룹 대표 앨범과 다른 제공처의 실제 곡 ID로 저장한 심의 snapshot도 원래 선택 범위대로 표시한다.
- TypeScript·변경 파일 ESLint·diff 검사 통과. 기존 `HEAD`에 이번 변경만 올린 격리본에서 252개 검사와 `npm run build -- --webpack`이 통과했고 정적 페이지 87개를 생성했다.
- 운영 DB를 읽기 전용으로 조회하는 실제 서비스 경로에서 아티스트 목록과 상세 화면의 앨범 수가 모두 14개인지 확인했다. 검증 전 사본과 비교해 원본 26개 앨범·108개 수록곡·97개 작품과 저장 버전이 동일했다. 내부 회원·작업 식별자가 포함된 사본은 저장소에 올리지 않는다.

별도 문서 처리와 Mac 앱의 미커밋 작업 21개는 변경하지 않고, 이번 변경 16개 파일만 반영한다. 운영 배포 결과는 완료 후 기록한다.
