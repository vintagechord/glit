## 변경

- **처리 단계 분류** (`src/lib/admin/submission-stages.ts`)
  - 단계: 작성 중 / 결제 전 / 입금 확인 대기 / 결제 완료·접수 전 / 심의 중 / 결과 안내 대기 / 통보 완료 / 환불.
  - 대시보드 집계, 접수 관리의 `stage` 필터, 목록 배지가 같은 정의를 씁니다. 테스트가 모든 상태 조합에서 필터와 분류가 일치하는지 확인합니다.
- **대시보드** (`/admin`)
  - 단계별 건수를 보여줍니다.
  - 입금 확인 대기 주문, 결과 안내 대기 건(수신 이메일 없음 표시)을 보여줍니다.
  - 메일 실패(14일), 최근 접수, 그룹별 관리 메뉴를 보여줍니다.
- **멜론/지니 링크 심의자료 생성**: `/admin/review-docs/links`로 옮겼습니다.
- **접수 상세**
  - 처리 단계 배지와 작성 중 안내를 표시합니다.
  - 업로드 기록(서버에 도착한 업로드 요청)을 표시합니다.
  - **결과 안내 수신 이메일** 카드를 추가했습니다. 비회원은 `guest_email`, 이메일 없는 소셜 회원은 이 신청서의 `applicant_email`을 저장합니다.
  - 계정 이메일과 회원이 저장한 알림 이메일은 바꾸지 않습니다.
- **관리자 직접 접수** (`/admin/intake`)
  - 기준파일(HWP·HWPX·DOC·DOCX, 4MB 이하)을 데스크와 같은 분석기로 읽습니다(`tools/onside-desk/manual-import.mjs`).
  - DOC는 서버용 판독기(`src/lib/admin/legacy-word-doc.ts`)가 표 구조를 살려 읽습니다. 실제 기준파일 5개에서 데스크(textutil)와 같은 결과를 냈고, 메모·이메일 칸은 더 정확하게 읽었습니다.
  - 양식 안내문은 걸러냅니다.
  - 음반은 기존 `admin_register_guest_album`, 뮤비는 새 `admin_register_guest_mv`(마이그레이션 `20261105120000`)로 비회원 접수를 만듭니다. 브라우저 요청 ID가 조회 코드여서 재시도해도 중복이 생기지 않습니다.
  - 음원·영상 파일 첨부는 포함하지 않습니다.
- **고객 화면**
  - 파일 이메일 제출 제목에서 접수번호를 뺐습니다. 예: `[MV심의 파일] 아티스트 / 곡명 / 온라인용`.
  - 현재 상태 표기를 바꿨습니다. 전체 방송사가 접수되면 「전체 방송사 접수 완료」, 한 곳이라도 결과가 나오면 「결과 통보 중」입니다.
  - 현재 상태 아래의 「진행표 보기」·「신청서 확인」 버튼을 없앴습니다. 결제 버튼은 유지합니다.
