# 아티스트 통합 검색과 멜론 전체 앨범 수집

2026-10-28 KST. 회원은 플랫폼을 선택하지 않고 아티스트 이름을 입력한다. 온사이트 서버가 멜론·지니·Apple Music과 설정이 완료된 Spotify·YouTube를 동시에 검색한다. Spotify·YouTube 키 발급·등록·활성화 보류는 유지한다. 설정이 필요한 서비스의 안내와 공식 검색 링크는 화면의 `검색 서비스 안내 · 공식 사이트에서 찾기`에 남겼다.

검색은 서비스별 첫 후보 최대 20개를 모아 이름 일치도를 기준으로 표시한다. 제공처와 ID가 다른 후보를 이름만으로 병합하지 않는다. 회원은 프로필을 확인하고 자신의 아티스트를 선택한다. 동일 검색 요청 공유, 60초 캐시, 10분간 유지되는 검색 결과 식별자로 중복 호출과 페이지 간 결과 이동을 줄였다. 서비스별 17초 제한과 취소 신호를 적용하고 일부 실패 시 나머지 결과를 제공한다. 검색 실패 결과는 새 검색에서 재시도한다. 서버 재시작·캐시 만료 시 다시 검색하도록 안내한다. 자동 검색의 Apple 추가 이미지 조회는 생략하며 이름·프로필 검색과 기존 공개 인덱스는 유지한다.

멜론 수집 중단 원인은 공식 아티스트 목록에 있는 참여 앨범에도 선택한 아티스트의 가창 ID를 요구한 데 있었다. 빈티지코드(882441)는 14개 중 5개 앨범이 다른 가수의 곡을 포함해 기존 코드가 두 번째 앨범에서 중단됐다. 이제 공식 아티스트 목록으로 확인한 참여 앨범을 저장하며, 가창 연결이 확인되지 않은 곡은 관리 대상으로 자동 지정하지 않는다. 앨범 상세에서는 전체 수록곡 수와 읽기 전용 곡 목록을 제공하고, 심의·등록 작업은 기존 관리 대상 곡 범위를 유지한다.

전체 앨범 분류를 명시하고 선언된 전체 개수, 각 페이지 개수, 중복 ID, 앨범 수록곡 개수를 대조한다. 추천 영역은 앨범 목록에서 제외한다. 누락·잘린 응답을 완료 처리하지 않는다. 기존 v1 커서와 중단된 작업의 재개를 유지하며, 공개 목록의 미공개·삭제 자료까지 확보했다고 표시하지 않는다. 기존에 중단된 작업은 `다시 불러오기`, 이미 완료된 작업은 `새 발매작 확인`으로 재조회한다.

## 검증

- `node --test --import tsx tests/music-archive-*.test.ts tests/melon.test.ts`: 182개 통과.
- 실제 회원 화면을 모의 API로 실행한 Playwright 음악 관리·참여 앨범 검사: 24개 통과, 부분 실패와 빈 검색 결과를 구분하는 추가 검사 1개 통과. 자동 검색, 부분 실패, 서비스 구분, 한글 조합 입력, 오래된 응답 무시, 검색 페이지 식별자, 모바일 레이아웃, 심의 범위 보존을 확인했다.
- TypeScript, 변경 파일 ESLint, `git diff --check`, `npm run build -- --webpack` 통과.
- 공식 멜론 HTTPS 공개 페이지를 읽고 동일 응답을 수집기에 넣어 빈티지코드 14개 앨범·55개 수록곡·참여 앨범 5개·관리 대상 곡 42개를 15단계로 완료했다. 고객 라이브러리에 검증 데이터를 쓰지 않았다.
- 아이유(261143)는 공식 전체 앨범 목록 4페이지에서 각 15개, 총 60개 고유 앨범 ID와 마지막 페이지 종료를 확인했다. 60개 앨범의 상세 수록곡을 전부 검증한 것은 아니다.

DB 스키마·키·요금제 변경은 없다. 배포에는 이번 음악 관리 파일만 포함하고 별도 진행 중인 심의 문서·Mac 앱 변경은 포함하지 않는다. 코드 롤백은 이전 웹 배포로 가능하며 회원 자료나 수집 이력을 삭제하지 않는다.
