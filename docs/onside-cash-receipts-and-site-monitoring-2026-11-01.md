# 현금영수증 · 심의 데스크 사이트 관리 (2026-11-01)

사용자 요청 세 가지를 반영했다. 나의 심의 내역의 불필요한 표시 제거, 무통장 입금
현금영수증 신청·발급·PDF, 심의 데스크의 사이트 관리 메뉴다.

## 1. 나의 심의 내역

제목이 없는 발매 음반 URL 접수 건은 아티스트 카드 안에서 "발매된 음반 · URL 접수"와
날짜 줄을 보여주지 않는다. 상태 칩·선택·삭제는 그대로이며, 화면 낭독용 이름은 유지한다.
제목이 있는 항목은 기존처럼 제목과 날짜를 보여준다.

## 2. 무통장 입금 현금영수증

### 흐름

1. 고객이 장바구니의 무통장 입금 폼에서 **개인 소득공제**(휴대폰 번호 또는 현금영수증
   카드 번호) 또는 **사업자 지출증빙**(사업자등록번호, 검증식 확인)을 선택한다.
   주문내역에서도 입금 대기·결제 완료 주문에 신청·변경·취소할 수 있다.
2. 관리자가 접수 상세에서 운영 단계를 **결제완료**로 바꾸면 입금이 확인된다.
3. 발급
   - **자동**: Vercel에 `INICIS_INIAPI_KEY_PROD`, `INICIS_INIAPI_IV_PROD`가 있으면 결제완료
     직후 KG이니시스 현금영수증 별도발행 API(INIAPI v2 `/v2/pg/receipt`)로 발급한다.
   - **수동**: 키가 없으면 관리자가 홈택스(또는 이니시스 관리자)에서 발급하고
     `/admin/cash-receipts`에서 승인번호와 발급 일시를 입력한다.
4. 발급되면 고객 주문내역과 관리자 화면에서 **PDF 다운로드**가 열린다. PDF는 승인번호·
   거래일시·용도·마스킹된 발급 번호·공급가액·부가세·합계·가맹점 정보를 담은 확인서다.
   현금영수증의 효력은 국세청에 등록된 승인번호에 있으며, 고객은 홈택스에서도 조회한다.

### 운영 메모

- 관리자 화면: 관리자 홈 → **현금영수증 발급** (`/admin/cash-receipts`). 발급 필요(결제완료),
  입금 대기, 발급 완료, 취소 탭이 있다. 관리자는 전체 발급 번호를 보고, 고객은 마스킹된
  번호만 본다.
- 발급 취소는 이 화면에서 기록만 한다. 홈택스·이니시스에서 먼저 취소한 뒤 사유를 남긴다.
- 이니시스 응답을 받지 못하면 "결과 확인 필요"로 남긴다. 이니시스 관리자에서 발급 여부를
  확인한 뒤 다시 발급하거나 승인번호를 직접 입력한다.
- 가격은 부가세 포함(일반과세)으로 보고 공급가액 = 합계 ÷ 1.1(반올림), 부가세 = 나머지로
  계산한다.
- 이니시스 자동 발급 연동은 이니시스 테스트 서버(`stginiapi.inicis.com`, MID `INIpayTest`)에서
  소득공제·지출증빙 모두 `resultCode 00`과 승인번호를 확인했고, 잘못된 키는 해시 불일치로
  거절되는 것을 확인했다. 운영 MID에서 별도발행 사용 가능 여부는 KG이니시스(1588-4954)에
  확인한다. INIAPI Key·IV 위치: 가맹점관리자 ▶ 상점정보 ▶ 계약정보 ▶ KEY 정보.

### 데이터

- 마이그레이션 `20261101120000_cash_receipts_and_site_monitoring.sql`
  - `submission_order_cash_receipts`(주문당 1건, service role 전용). 발급 완료 상태는 승인번호·
    발급 일시·금액이 있어야 저장된다.
  - `site_monitoring_snapshot()`(service role 전용): 심의 데스크 사이트 관리용 읽기 전용 요약.
- PDF는 `pdf-lib`와 나눔고딕(OFL, `src/assets/fonts/nanum-gothic`)을 사용한다. pdf-lib의 글꼴
  부분 포함이 나눔고딕 글자를 누락시켜 글꼴 전체를 넣는다. PDF는 약 1.6MB다.

## 3. 심의 데스크 2.4.0 · 사이트 관리

| 영역 | 확인 내용 | 기준 |
| --- | --- | --- |
| 온사이드 사이트 | `/api/health` 응답·오류, www→대표 주소 연결 | 응답 실패·오류 = 문제, 4초 이상 = 주의 |
| Vercel | 최근 Production 배포, 도메인 연결 (토큰 필요) | 배포 실패 = 주의, 도메인 설정 오류 = 문제 |
| Supabase | Auth·Storage 응답, DB 용량(500MB), Storage(1GB), 이번 달 로그인 회원(5만), 메일·예약 작업 실패, 현금영수증 대기, 입금 대기 주문, 1주 무활동 정지 위험 | 사용량 70% 주의, 90% 문제 |
| Backblaze B2 | 저장 용량(무료 10GB), 종류별 용량, 큰 파일, 180일 지난 파일, 하루 지난 미완료 업로드 | 사용량 70% 주의, 90% 문제 |
| 가비아 | A·CNAME이 Vercel 값과 같은지, 네임서버, SSL 만료(20일 주의·7일 문제), 도메인 만료(60일 주의·30일 문제) | |

- Vercel 토큰은 데스크 **점검 설정**에 붙여넣는다. 데이터 폴더의 `monitor.json`(권한 600)에만
  저장하며 백업·화면 응답에 포함하지 않는다.
- 창을 닫아도 10분마다 확인하고, 새 문제가 생기면 Mac 알림을 한 번 보낸다(설정에서 끌 수 있다).
- B2 목록 조회는 30분마다, 수동 새로고침은 최소 2분 간격으로 실행한다(무료 계정의 일일
  거래 한도 보호).
- API로 제공되지 않는 값(Vercel Hobby 사용량, Supabase 전송량, B2 결제 수단·Caps)은 각
  대시보드 버튼으로 연결한다. 2026-11-01 기준 B2 사용량은 80MB(0.8%)다.
- Vercel 이전으로 데스크 필증 업로드 한도를 웹과 같은 4MB로 맞췄다.

## 배포 순서

1. `supabase db push --linked`로 `20261101120000` 적용(사용자).
2. PR 병합 → Vercel Production 배포.
3. 데스크 2.4.0 빌드·설치(`tools/onside-desk/build-mac.mjs` → `install-mac.mjs`).

마이그레이션 전에 배포되면 주문 목록은 현금영수증 없이 정상 동작하고, 신청 저장은 실패를
안내하며, 데스크는 "점검 함수 없음"을 표시한다.
