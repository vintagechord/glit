## 2. 배포 순서와 대표 확인 사항

1. **마이그레이션:** `20261103120000_submission_insert_guard.sql` 운영 적용 완료(2026-11-03, `supabase migration list --linked`로 확인).
2. **모바일 ISP 카드 실결제 확인:** 배포 후 휴대폰에서 BC 또는 국민카드(ISP/안전결제)로 소액 결제 1건을 진행해 주문이 결제 완료로 기록되는지 확인하고 환불한다.
3. **과거 모바일 결제 대조:** 모바일 카드 결제를 켠 2026-10-31 이후 이니시스 가맹점관리자의 모바일 승인 내역과 `/admin/payments`를 대조한다. 이니시스에는 승인됐는데 주문이 `CARD_PENDING`인 건이 있으면 이번 1번 문제로 기록이 누락된 것이다.
4. **Supabase 회원가입 설정(앱 코드로는 막을 수 없음):** 공개 설정이 `disable_signup=false`, 이메일 가입 허용이다. 누구나 anon 키로 `/auth/v1/signup`에 남의 이메일과 자기 비밀번호를 보내면 Supabase가 자체 확인 메일을 보내고, 피해자가 링크를 누르면 공격자 비밀번호로 계정이 확정된다. 앱은 `admin.generateLink`와 자체 메일 릴레이를 쓰므로 Supabase 기본 "Confirm signup" 메일은 쓰지 않는다. 대시보드 ▶ Authentication ▶ Email Templates ▶ Confirm signup 본문에서 확인 링크(`{{ .ConfirmationURL }}`)를 빼거나, Before User Created 훅으로 service role이 아닌 이메일 가입을 거부한다.
5. **개인정보처리방침:** 대표 결정으로 국외 이전 항목의 Vercel·Supabase 위치를 대한민국(서울)으로 고치고 시행일을 2026-11-03으로 바꿨다(한·영). 실제 이전은 2026-11-02에 이미 끝나 사실을 바로잡는 변경이다. 방침의 "시행 7일 전 공지" 문구는 그대로 두었다.
6. **채팅 토큰:** 이번 배포 전까지 공용 채널로 토큰이 나갔다. 상담 대화가 많지 않다면 지금 열린 대화를 정리하는 것으로 충분하다. 접근 토큰 일괄 교체는 방문자가 기존 대화를 잃으므로 선택 사항이다.

## 3. 확인했지만 이번에 고치지 않은 것

고치려면 설계 결정이나 큰 변경이 필요한 항목이다. 심각도 순.

- **고객이 관리자 메모를 읽을 수 있음(중간):** `submissions.admin_memo`는 소유자 SELECT 정책에 열려 있고, `refund_submission_order`·`resolve_uncertain_submission_payment`는 관리자 메모를 `submission_orders.note`에 복사한다. 컬럼 단위 권한으로 막으려면 회원 세션의 모든 `select` 사용처를 함께 정리해야 한다.
- **환불 후 현금영수증(중간):** 환불을 기록해도 발급된 현금영수증이 ISSUED로 남고 고객 PDF도 계속 내려받을 수 있다. 결과 불명 건(FAILED + "[결과 확인 필요]")을 고객이 수정·삭제할 수 있고, ISSUING에서 멈춘 건을 풀 방법이 없다. 자동 발급 키를 넣기 전에 정리해야 한다.
- **결제 결과 안내(중간):** 승인 후 DB 기록 실패 등 "확인 필요" 상황에서도 고객에게 "결제 처리에 실패했습니다"가 표시되어 재결제할 수 있다.
- **신청서 동시 편집(중간):** 저장 시 마지막으로 불러온 버전을 비교하지 않아, 오래된 탭·기기가 최신 내용을 덮어쓸 수 있다. 비회원 초안 생성은 같은 토큰의 기존 초안을 새 것처럼 돌려줘 빈 폼으로 덮어쓸 수 있고, 장바구니 항목 "수정"이 작성 중 초안의 저장 위치를 덮어쓴다.
- **업로드 복구(중간):** 보완 자료(supplements) 멀티파트 업로드는 완료 호출이 한 번 실패하면 다시 완료할 수 없고, 한 파트 실패 시 처음부터 다시 올려야 한다. 7일 스테이징 만료와 실패한 멀티파트 정리가 실행되지 않아 B2 비용이 남는다.
- **보관 파일 일괄 삭제(확인 필요):** 온라인 MV는 영등위 등급이 나오면 완료로 보고, Mnet·ETN 방송 심의가 진행 중이어도 영상을 삭제 대상에 넣는다. 의도한 정책인지 확인이 필요하다.
- **관리자 삭제(낮음~중간):** 환불된 신청을 삭제하면 `submission_payments`의 카드 승인 기록(TID)이 함께 지워진다. 테스트 주문 정리에 쓰고 있다면 유지하되, 실거래 환불 건은 삭제하지 않는다.
- **비회원 주문 로그인 후 미표시, 모바일 결제 취소 상태 표시, 노래방 승인 중복 요청 시 망취소 가능성, 구독 결제·환불 레거시 경로(`/subscription`, `/api/wmadmin/...`)가 키만 넣으면 살아나는 구조**: 낮음, 별도 정리 권장.
- **번역 API 비용:** `/api/translate`는 로그인 없이 쓸 수 있고 인스턴스 메모리 기준 제한만 있다. 이번 헤더 수정으로 우회는 막았지만, 전역 일일 한도는 따로 두는 것이 안전하다.
- **채팅·문의 범람, 관리자 회원 목록 200명 상한, 매거진 대표 이미지 버킷 제한 없음, 이메일 워커 60초 제한(메일 점유 180초와 함께 조정 필요)**: 낮음.
- **SEO·접근성:** `/en` 페이지는 서버에서 한국어로 렌더링되고 `<html lang="ko">`다. 스크롤 등장 섹션은 JS 없이 보이지 않고, 푸터 정책 링크는 버튼이며, 상단 배너 자동 회전에 일시정지가 없다. 일부 파스텔 상태 색상(매거진·노래방·크레딧 알림)이 남아 있다.
