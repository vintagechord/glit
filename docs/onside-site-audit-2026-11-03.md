## 2. 배포 순서와 대표 확인 사항

1. **마이그레이션:** `20261103120000_submission_insert_guard.sql` 운영 적용 완료(2026-11-03, `supabase migration list --linked`로 확인).
2. **모바일 ISP 카드 실결제 확인:** 배포 후 휴대폰에서 BC 또는 국민카드(ISP/안전결제)로 소액 결제 1건을 진행해 주문이 결제 완료로 기록되는지 확인하고 환불한다.
3. **과거 모바일 결제 대조:** 모바일 카드 결제를 켠 2026-10-31 이후 이니시스 가맹점관리자의 모바일 승인 내역과 `/admin/payments`를 대조한다. 이니시스에는 승인됐는데 주문이 `CARD_PENDING`인 건이 있으면 이번 1번 문제로 기록이 누락된 것이다.
4. **Supabase 회원가입 설정(앱 코드로는 막을 수 없음):** 공개 설정이 `disable_signup=false`, 이메일 가입 허용이다. 누구나 anon 키로 `/auth/v1/signup`에 남의 이메일과 자기 비밀번호를 보내면 Supabase가 자체 확인 메일을 보내고, 피해자가 링크를 누르면 공격자 비밀번호로 계정이 확정된다. 앱은 `admin.generateLink`와 자체 메일 릴레이를 쓰므로 Supabase 기본 "Confirm signup" 메일은 쓰지 않는다. 대시보드 ▶ Authentication ▶ Email Templates ▶ Confirm signup 본문에서 확인 링크(`{{ .ConfirmationURL }}`)를 빼거나, Before User Created 훅으로 service role이 아닌 이메일 가입을 거부한다.
5. **개인정보처리방침:** 대표 결정으로 국외 이전 항목의 Vercel·Supabase 위치를 대한민국(서울)으로 고치고 시행일을 2026-11-03으로 바꿨다(한·영). 실제 이전은 2026-11-02에 이미 끝나 사실을 바로잡는 변경이다. 방침의 "시행 7일 전 공지" 문구는 그대로 두었다.
6. **채팅 토큰:** 이번 배포 전까지 공용 채널로 토큰이 나갔다. 상담 대화가 많지 않다면 지금 열린 대화를 정리하는 것으로 충분하다. 접근 토큰 일괄 교체는 방문자가 기존 대화를 잃으므로 선택 사항이다.

## 3. 2차 조치(같은 날): 남은 항목 전부

대표 요청으로 1차에서 미룬 항목을 모두 고쳤다. 영역별로 나눠 작업한 뒤 하나로 합쳤다(PR "Fix the remaining site audit findings").

### 결제·주문·현금영수증
- **모바일 카드 결제가 항상 실패하던 문제:** DB 감사 로그 정리 함수(`scrub_payment_audit_json`, 0084)가 주문 기록의 `channel: "mobile"` 표시를 지워, 모바일 결제 콜백이 승인 요청 전에 모두 거부됐다. 승인 전에 거부되므로 청구된 건은 없다. 허용 목록을 앱과 맞추고, 두 목록이 어긋나면 실패하는 테스트를 추가했다.
- **환불과 현금영수증:**
  - 환불·삭제 시 미발급(REQUESTED/FAILED) 현금영수증을 취소한다.
  - 이미 발급된 영수증은 `/admin/cash-receipts` ▶ 처리 필요에 "홈택스 취소 필요"로 표시한다.
  - 환불 주문은 고객이 영수증 PDF를 받을 수 없다.
- **결과 불명 현금영수증:**
  - 새 상태 `UNCERTAIN`을 추가했다. 고객은 수정·삭제할 수 없고, 관리자가 "발급됨/미발급"으로 확정한다. 5분 넘게 ISSUING에 멈춘 건도 같은 방법으로 확정한다.
  - 발급 시작 시 읽은 시점의 내용과 일치할 때만 발급한다.
- **결제 결과 안내:** 승인 여부가 불확실하면 "결제 확인 중입니다. 다시 결제하지 마세요"와 연락처를 보여준다. PC·모바일 모두 해당하고, 주문 목록의 확인 필요 건에도 표시한다.
- **로그인 후 비회원 주문:** 같은 브라우저의 비회원 토큰으로 주문을 계속 볼 수 있다(읽기 전용, 소유권 이전 없음).
- **모바일 결제 취소:** PC에서 창을 닫은 것과 같은 상태(결제 대기)로 처리한다.
- **노래방 카드 승인:** 승인 전 claim을 추가해 중복 요청이 기록된 결제를 망취소하지 못하게 했다.
- **늦게 도착한 승인:** 10분 잠금 만료로 확인 필요가 된 주문에 승인이 늦게 도착하면 결제 완료로 맞춘다.
- **관리자 메모:** 주문 메모(`submission_orders.note`)에는 고정 안내문만 남기고, 관리자 자유 문구는 관리자 메모에 이어 쓴다.
- **결제 기록 보관:** 결제 기록이 지워지기 직전 `submission_payment_archive`에 복사된다. 환불된 테스트 주문을 삭제해도 TID가 남는다. `/admin/payments`에 "삭제된 접수 보관" 필터를 추가했다.
- **구독 결제:**
  - 레거시 구독 결제·환불 경로는 `ONSIDE_SUBSCRIPTION_BILLING_ENABLED=1`일 때만 동작한다(기본 꺼짐, 404/410).
  - `/api/wmadmin/...`은 삭제했다.
  - 구독 환불 RPC는 관리자 여부를 직접 확인한다.
- **현금영수증 INIAPI 설정:** 빌링 키로 대체하지 않고 `INICIS_INIAPI_KEY_*`/`INICIS_INIAPI_IV_*`만 사용한다.

### 신청서 흐름
- **오래된 탭의 덮어쓰기:** 저장 시 마지막으로 불러온 버전(`updated_at`)을 함께 보내, 다른 창·기기에서 먼저 저장했으면 저장을 거부한다. 이때 입력 내용은 기기에 보관하고 "최신 내용 다시 불러오기"를 안내한다.
- **비회원 초안 덮어쓰기:** 기존 초안을 돌려줄 때 `reused: true`를 알려 새 초안이 아니라 이어하기로 연다.
- **장바구니 "수정"과 작성 중 초안:** 수정을 눌러도 작성 중이던 비회원 초안 위치를 잃지 않는다(보관 목록 최대 10개).
- **로그인 후 비회원 초안:** 계정으로 옮겨진 초안의 토큰만 지운다.
- **비회원 조회 페이지 다운로드:** 로그인한 회원도 비회원 조회 페이지에서 파일을 받을 수 있다.
- **삭제 API:** 미결제 초안만 실제로 삭제한다. 결제·환불 건은 숨기고, 입금 대기 등은 거부한다.
- **PRE_REVIEW 해석:** 결제된 PRE_REVIEW를 초안으로 취급하던 곳(초안 이어하기, 내 음악 관리)을 바로잡았다.
- **빈 초안 자동 삭제:** 내용이 있는 초안은 지우지 않도록 판단 기준을 넓혔다.
- **영문 회원 페이지:** 영어 제목과 오류·빈 화면 문구를 붙였다.

### 업로드·저장소
- **보완 자료 업로드:** 완료 처리가 한 번 실패해도 다시 완료할 수 있다. 파트별로 재시도·이어올리기를 하고, 3개씩 동시에 올린다.
- **7일 지난 미저장 업로드 정리:** 10분마다 정리 작업(`onside-storage-cleanup`)이 실행된다. 이 작업은 다음도 정리한다.
  - 실패·중단된 멀티파트
  - 삭제된 신청의 진행 중 업로드
  - 매거진 미사용 이미지
- **단일 업로드 완료:** `/init` 때 승인된 파일 정보만 쓴다(`upload_put_grants`). 확장자와 형식이 모두 맞아야 업로드할 수 있다.
- **B2 다운로드 링크:**
  - 항상 "첨부파일로 저장"으로 받는다. 필증·등급 이미지도 새 탭이 아니라 다운로드된다.
  - 24시간짜리 다운로드 링크를 DB에 저장하지 않는다.
- **보관 파일 일괄 삭제:**
  - 중간에 끊겨도 다시 시도한다(`purge_confirmed_at`).
  - 온라인 MV는 방송 심의까지 모두 끝나야 삭제 대상이 된다.
- **기타:**
  - Supabase `submissions` 버킷 직접 업로드를 막았다.
  - 매거진 이미지 버킷에 20MB·이미지 형식 제한을 두고, 요청 횟수도 제한한다.
  - 노래방 첨부는 허용 형식만 받는다.

### 인증·관리자·채팅·API
- **관리자 메모:** 관리자 전용 테이블 `submission_admin_memos`로 옮겼다. `submissions.admin_memo`에 쓰면 트리거가 이 테이블로 옮기고, 기존 메모 뒤에 이어 쓴다.
- **비밀번호 변경:** 현재 비밀번호를 확인한다. 소셜 전용 계정은 거부하고, 변경 후 다른 기기는 로그아웃된다.
- **남이 미리 만든 미확인 계정:** 남의 이메일로 Supabase에 직접 만들어 둔 미확인 계정(앱 표시 없음, 로그인 이력 없음)은 정상 가입·재발송·찾기 때 지우고 정상 절차로 진행한다.
- **API 한도:**
  - 번역 API: IP별 영구 한도와 사이트 전체 하루 예산이 있다. 예산을 다 쓰면 브라우저 무료 번역으로 넘어간다.
  - 상담 채팅: 새 대화 수를 제한하고, 열린 대화는 방문자당 3개까지다.
  - 문의와 노래방 신청: 요청 횟수를 제한한다.
- **관리자 목록:** 채팅·문의·회원·노래방 목록에 페이지 넘김을 추가했다. 회원 목록은 이메일로 검색할 수 있다.
- **이메일 워커:** 실행 시간은 300초다. 남은 시간이 메일 1건의 최악 소요 시간보다 짧으면 새 메일을 잡지 않는다.
- **워커 토큰:** SHA-256 다이제스트로 비교한다.
- **이미지:** 최적화와 배너 저장 모두 우리 Supabase 호스트, B2 버킷, genie만 허용한다.
- **`?error=` 안내:** 정해진 코드만 화면에 보여준다.

### 화면·접근성
- **영문 페이지:** `/en`은 첫 화면부터 `lang="en"`이다. 페이지를 이동하면 바로 번역한다. 서버에서 영어로 렌더링하는 것은 범위 밖이다.
- **JS 없는 방문자:** JS가 없어도 등장 애니메이션 섹션이 보이고, 모션 줄이기 설정을 따른다.
- **푸터 정책 링크:** 실제 링크로 바꿨다. 환불·파일 정책은 `/terms#refund`, `/terms#file-policy`에도 게시했다.
- **띠배너:** 마우스를 올리거나 포커스하면 멈추고, 일시정지 버튼이 있다.
- **색상:** 약 60개 파일의 파스텔 상태 색상을 바우하우스 팔레트로 바꿨다. `tests/house-palette.test.ts`가 다시 들어오는 것을 막는다.
- **가이드 가격:** 관리자 패키지 수정이 바로 반영되고, 테스트 패키지는 빠진다.
- **기타:** 비밀번호 찾기·노래방·영문 인증 페이지에 메타데이터를 넣었다. 금칙어 캐시를 1시간으로 바꿔 앨범 신청 페이지 재생성 주기도 1시간이 됐다.

### 남은 범위 밖·참고
- 사용자가 지운 미저장 파일은 다른 기기에서 최대 7일까지 다시 보일 수 있다. 스테이징이 만료되면 정리된다.

- `/en` 마케팅 페이지를 서버에서 영어로 렌더링하는 것은 별도 작업이다.
- Supabase에 맞춤 SMTP를 연결하게 되면, 그때 Confirm signup 템플릿의 확인 링크를 지운다. 지금은 기본 메일 서버라 팀원 주소로만 발송된다.
