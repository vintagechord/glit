# 온사이드 심의·발매·방송 신청 연결 변경

작성: 2026-10-27. 사용자 승인으로 운영 웹·DB·Mac 앱에 적용했다. Spotify·YouTube API 키 설정은 사용자 요청으로 후속 작업으로 보류한다.

## 신청 화면과 심의데스크

- `/dashboard/new`의 편성 보장 및 Mnet·ETN 상담 안내 문단을 제거했다.
- 자동 저장 배지를 제거하고 비회원 가능 표시를 선택 카드 아래로 이동했다.
- 신청 화면과 신청 단계 하단의 문의 링크를 `문의하기` 버튼으로 통일했다. 기존 새 창 동작과 영문 경로 연결은 유지한다.
- 심의데스크의 목록 휴지통에서 삭제 건수를 확인하고 비울 수 있다. 해당 Mac의 원본·생성 파일·작업 이력을 삭제하며 온라인 신청·심의 결과와 별도 백업은 유지한다. 온라인 항목은 최소 식별 기록을 남겨 다음 동기화에서 다시 나타나지 않게 한다. 동시 복원·삭제와 작업 중 삭제를 막으며, 일부 파일 삭제 실패 시 남은 항목을 재시도할 수 있다.

## 아티스트와 앨범

아티스트를 이름으로 검색하고 제공처·식별자·공식 프로필을 비교한 뒤 연결한다. 표시 이름만으로 다른 제공처의 아티스트나 동명이인 앨범을 자동 병합하지 않는다. 앨범 가져오기는 기존 소유자별 작업 큐와 원자적 커서 저장을 사용하며, 중단 후 재시도할 때 사용자가 수정한 자료와 심의 이력을 보존한다.

일부 곡에만 심의 이력이 있으면 나머지 곡별로 신청할 수 있다. 진행 중 접수는 상세 화면의 결제·자료 보완 경로로 연결한다. 완료된 곡은 기존 심의 결과를 확인한 뒤 `다른 방송사 심의 신청`에서 추가 대상 방송사를 선택할 수 있다.

| 제공처 | 구현 범위 | 운영 조건 |
| --- | --- | --- |
| 멜론·지니 | 공개 아티스트 이름 검색, 선택한 ID의 앨범과 트랙 가져오기 | 새 DB 마이그레이션. 공개 페이지 구조·접근 제한이 바뀌면 재확인 필요 |
| Apple Music | 기존 이름·초성 검색과 앨범 가져오기, 검색 캐시 실패 처리 보완 | 기존 설정 사용 |
| Spotify | 공식 API 이름 검색, 아티스트 검증, 앨범·트랙 페이지별 가져오기, 선택 음원의 심의 신청 연결 | `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET`, 사용 가능한 앱 접근 범위, 새 DB 마이그레이션 |
| YouTube | 공식 API 이름 검색으로 채널 후보 조회·확인·연결 | `YOUTUBE_DATA_API_KEY`, YouTube Data API v3 사용 설정, 새 DB 마이그레이션 |

YouTube 채널·영상·재생목록만으로 공식 앨범 발매일과 수록곡을 확정하지 않는다. 같은 아티스트의 멜론·지니·Spotify·Apple Music 연결에서 발매 정보를 가져오도록 안내한다. 키가 없는 제공처는 검색 불가 이유와 공식 사이트 검색·링크 연결을 제공한다. 키는 서버 전용이며 `NEXT_PUBLIC_` 접두사를 사용하지 않는다.

Spotify는 현재 검색 최대 10개 후보를 사용한다. 앨범/트랙 수집은 고정 API 주소와 검증한 ID로 요청하고, 외부 응답의 `next` URL을 그대로 따라가지 않는다. 응답 크기, 페이지 수, 트랙 소속, 실제 달력 날짜와 저장 커서를 검증한다. 트랙 전체를 확인하기 전에는 앨범을 완성본으로 저장하지 않는다.

공식 구현 근거: [Spotify 검색](https://developer.spotify.com/documentation/web-api/reference/search), [아티스트 앨범](https://developer.spotify.com/documentation/web-api/reference/get-an-artists-albums), [앨범 정보](https://developer.spotify.com/documentation/web-api/reference/get-an-album), [트랙 페이지](https://developer.spotify.com/documentation/web-api/reference/get-an-albums-tracks), [Client Credentials](https://developer.spotify.com/documentation/web-api/tutorials/client-credentials-flow), [YouTube 채널 검색](https://developers.google.com/youtube/v3/docs/search/list), [채널 확인](https://developers.google.com/youtube/v3/docs/channels/list), [Google API 키 헤더](https://docs.cloud.google.com/apis/docs/system-parameters).

## 적격 음원의 방송 신청

기존 방송국별 적격 음원 선택과 신청 초안에 프로그램 편성 안내, 시간대·참여 방식 필터, 공식 코너 안내와 참여 링크를 추가했다. 확인한 프로그램만 구체적인 시간을 표시하며 특집·개편·지역 차이는 공식 페이지에서 확인하도록 한다.

사연과 곡을 함께 신청하는 게시판, 제작진이 사연에 맞춰 곡을 고르는 코너를 구분한다. 준비 체크리스트와 최근 선곡표 확인, 실제 경험과 곡의 연결 이유, 코너 주제와 마감 확인 방법을 제시한다. 방송 후에는 사연 소개와 곡 송출을 따로 기록하고 방송일·선곡표 또는 다시듣기 주소·다음 확인일을 남길 수 있다. 기록은 기존 작업공간과 TXT 내보내기를 사용하며 자동 방송 신청·자동 알림으로 표시하지 않는다.

프로그램별 공식 근거와 확인일은 `src/lib/radio-program-plans.ts` 및 화면에 포함되어 있다. 방송국 게시판에 글을 자동 게시하거나 제작진에게 메시지를 보내는 동작은 추가하지 않았다.

## 2026-10-29 접수자 기본값과 신청 안내

일반 음반 신청과 내 음악 관리에서 시작한 신청 모두 로그인한 회원의 이름·이메일·연락처를 접수자 기본값으로 사용한다. 인증 이메일이 없는 네이버·카카오 회원은 프로필에 저장한 알림 수신 이메일을 사용한다. 없는 정보는 빈칸으로 두며, 회원 정보가 채워진 필드도 직접 수정할 수 있다. 내 음악 관리에서 시작한 신청의 접수자 정보는 처음부터 펼쳐 보여준다. 비회원은 회원 프로필을 조회하지 않으며 기존 직접 입력 흐름을 유지한다.

내 음악 관리의 신청 제목을 “음원만 첨부하고 심의를 신청하세요”로 변경했다. 이미 앨범 정보를 불러왔으므로 아래 신청 버튼을 눌러 음원을 첨부하고 접수를 진행할 수 있다는 내용으로 안내한다. 직접 입력 버튼과 새 입력 창 제목은 “심의 내역 직접 입력”으로 통일했다.

프로필이 없으면 가입 시 저장한 이름·연락처를 기본값으로 사용하고, 수정한 프로필 정보가 있으면 이를 우선한다. 접수자 기본값·소셜 수신 이메일·비회원 분리와 기존 신청 단계 단위 검사 18개, 음악 관리 브라우저 검사 43개, 접수자 필드 표시·직접 입력·수정 브라우저 검사 3개를 통과했다. 프로필 조회는 로그인한 본인의 `user_id`로 제한하며 회원 정보나 접수 결과를 변경하는 운영 쓰기는 검증에 사용하지 않는다.

## 2026-11-03 신청서 정보 동기화와 가요심의요청서 배치

실제 결제가 들어온 두 건(비회원 대리 접수 1건, 멜론 링크 접수 1건)에서 고객 결과 페이지의 작성 신청서와 관리자 신청 상세 원문이 비어 있던 원인을 고쳤다. 결제·심의 결과·주문 데이터는 변경하지 않았다.

- **비회원 결과 페이지의 신청서 항목.** `/track/[token]`이 발매일·장르·유통사·제작사·이전 발매·아티스트 유형·멤버·앨범 링크 열을 조회하지 않아 저장된 값도 `-`로 보였다. 회원 상세와 같은 열 목록에 비회원·신청자 연락처를 더한 공용 로더 `src/lib/submissions/customer-detail.ts`로 바꿨다. 조회 코드 검증(`user_id is null` + `guest_token`)은 로더 안에서 그대로 유지한다.
- **관리자 미리보기.** `/admin/submissions/customer-view?id=…`가 고객 결과 페이지를 같은 컴포넌트로 보여 준다. 접수 상세 상단의 **고객 결과 페이지** 칸에 미리보기 링크, 고객 주소(비회원 조회 링크 또는 회원 대시보드 주소), 비회원 조회 코드를 표시한다.
- **신청서 항목 보정.** 접수 상세의 신청 상세 원문 안에서 발매일·장르·유통사·제작사·아티스트 유형·성별·멤버·이전 발매를 직접 저장한다(`updateSubmissionAlbumInfoFormAction`). 고객 메일은 보내지 않고 처리 이력만 남긴다.
- **심의 데스크 → 온라인 접수 반영.** 데스크 2.8.0은 비회원 접수로 등록한 수동 음반 작업의 문서 정보 수정 저장·심의 자료 생성 시, 그리고 ‘온라인에 반영’ 버튼으로 앨범 정보와 곡·가사를 `POST /api/internal/review-desk/[id]`의 `album-info` 작업으로 보낸다. 서버는 `saveManagedAlbumInfo`(`src/lib/admin/album-info-save.ts`)로 제공된 값만 덮어쓰고, 트랙은 번호로 맞춰 수정·추가하며 삭제하지 않는다. 방송사 결과가 참조하는 트랙 ID는 유지된다. 발매일은 `YYYY-MM-DD`로 읽을 수 있을 때만 보내고, “솔로/그룹”이나 항목 안내 문구는 유형으로 추정하지 않는다.
- **멜론 링크 접수의 신청 상세.** 발매 음반(URL) 접수는 링크만 저장되고 심의자료 생성 때만 메모리에서 멜론·지니 정보를 합쳤다. 이제 같은 수집 결과를 접수 저장(SUBMITTED) 직후, 결제 완료 후속 처리, 심의자료 ZIP 생성 시, 그리고 접수 상세의 **멜론·지니 앨범 정보 신청서에 반영** 버튼으로 접수에 기록한다(`src/lib/admin/released-album-hydration.ts`). 비어 있는 항목만 채우고 고객이나 관리자가 입력한 값은 바꾸지 않는다. 고객이 결제 전 신청서를 다시 저장하면 발매 음반 접수의 트랙이 비워지므로, 결제 완료 시점의 반영이 최종 보완 역할을 한다.
- **가요심의요청서(KBS).** 서버 템플릿을 데스크의 원본 HWP 복원본으로 교체했다. 음반제목 두 행 병합, 발매일/제작일, 기획사(제작사)/유통사, 심의요청곡수·담당자(연락처)·음반형태 행 구성이며, 머리글 `음반접수용(KBS가요심의곡)`은 오른쪽 탭으로 정렬한다. 타이틀곡은 `[T]`로 표시한다. 글꼴은 맑은 고딕으로 통일했다.

검증: 단위 테스트(앨범 정보 저장·멜론 반영·고객 로더·데스크 핸들러·템플릿 구성), 데스크 테스트 92개, TypeScript, ESLint. 템플릿은 LibreOffice로 PDF 렌더해 배치를 확인했다(이 환경에는 맑은 고딕이 없어 글자는 대체 글꼴로 표시됨).

## 2026-11-07 뮤직비디오 신청자 연락처·제작사 필수, 가사 Word 파일

이메일 없이 네이버로 가입한 회원이 온라인 MV(영등위)를 결제까지 마쳤는데 계정·프로필·신청서·결제 기록 어디에도 이메일과 전화번호가 없었고, 제작사도 비어 있었다(접수 `0a79da9b`). 고객이 빠뜨린 것이 아니라 신청 화면에 해당 입력란이 없었다. 2026-10-17 정리에서 MV 제작사 입력을 없앴고, 회원 MV 신청에는 신청자 연락처 칸이 처음부터 없었다.

- **신청자 이메일 필수, 연락처 선택.** 회원·비회원 모두 MV 신청서(직접 작성·양식 파일 제출 모두)의 신청자 정보에서 이메일을 받는다. 회원은 프로필(소셜 회원은 알림 수신 이메일)로 미리 채운다. 비회원 연락처는 더 이상 필수가 아니며, 숫자 9~11자리가 아니면 최종 점검에서 확인 권장으로만 표시한다. 서버는 최종 접수에서 신청자 이메일과 형식을 확인한다. 회원 신청은 `applicant_email`·`applicant_phone`에 저장하며, 이 칸이 생기기 전에 열어 둔 화면이 이메일을 보내지 않으면 계정 이메일로 대신한다(계정 이메일도 없으면 접수 거절). 관리자 상세는 신청서에 적은 연락처를 우선 보여 준다.
- **온라인(영등위) MV 제작사 필수.** 제작사가 비면 영등위 접수가 불가하므로 온라인 심의의 직접 작성 신청서에서 **뮤직비디오 제작사**를 다시 필수로 받는다. 안내: 심의 완료 후 영상 우측 상단에 등급 로고, 좌측 하단에 제작사명을 넣어야 하므로 대소문자·띄어쓰기·한글/영문 표기까지 똑같이 입력. 소속사 칸의 혼동되던 안내(“영상에 표시된 소속사·기획사명과 동일하게”)는 “아티스트의 소속사·기획사명”으로 바꿨다. TV 송출 신청과 양식 파일 제출은 웹 입력란 대상이 아니다.
- **MV 가사 Word 파일.** 관리자 접수 상세에 **가사 DOCX 다운로드**를 추가했다(`/api/admin/submissions/[id]/mv-lyrics`). 신청서 가사를 영등위 가사 양식(`lyrics-mv.docx`)으로 만들고, 외국어 줄에는 음반 서류와 같은 자동 `(번역 : …)`을 붙인다. 파일명은 데스크와 같은 `가사_아티스트_곡명`이며 데스크는 `.doc`, 웹은 서버에서 변환기를 쓸 수 없어 `.docx`로 만든다. 직접 입력한 가사가 없는(양식 파일 제출) 접수에는 버튼이 나오지 않는다.
